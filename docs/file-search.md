# 文件检索：Markdown 与 Excel 分开处理

Novex 不要求把所有知识都转成 Markdown。文字资料适合按段落读，报价表、库存表与明细表适合按列和条件查。两种路径都由 Pi / DeepSeek Harness 选择工具，Go 平台在每次读取前执行当前用户的文件权限。

## 已实现的路径

| 文件 | 上传时处理 | 对话时读取 | 回答证据 |
|---|---|---|---|
| MD / TXT / DOCX / 文字型 PDF | 提取 Markdown；保存文档 ACL 和文本关键词索引 | 当前用户授权的只读文件目录、原生文件工具，或 `search_documents` / `read_document` | 文档 ID；PDF 转换文本保留页码标题 |
| XLSX / UTF-8 CSV | 保留原文件；一次性提取工作表、表头、类型、原始行号、单元格及公式缓存 | `read_document` 获取列定义，再用 `query_spreadsheet` 精确筛选或关键词检索 | 文档 ID + 工作表 + 原始单元格范围 |
| 实时 HR / WMS 业务数据 | 注册外部 PostgreSQL 表、字段、身份映射和角色授权 | `list_resources` / `query_resource` | 受授权的实时数据库查询结果 |

这三条路径没有向量库、embedding 生成或自动语义切块。Excel 不生成 Markdown 数据副本，也不会把五万行整表送进模型上下文。

## Excel 怎样快速查

上传阶段只解析一次，原件私有存放在主库 `novex_documents.original`，索引位于 `novex_workbook_sheets` 和 `novex_workbook_rows`。原始业务库与知识索引分离。

- 工作表名和原始行号有复合主键，适合分页读取。
- 单元格保存为带类型的 JSONB；精确条件使用 JSONB GIN 索引，例如 SKU 等于 `HW-002499` 且月份等于 `2026-11`。
- 跨单元格关键词使用 PostgreSQL `pg_trgm` GIN 索引；`%` 和 `_` 按原字符匹配，不作为通配符。
- 数值列支持上下界；指定列的文本包含筛选也可用。这些条件并非都有专属索引，具体计划取决于选择性。很短或很常见的关键词、深分页和低选择性范围查询可能更慢。
- 每次最多返回 100 行、带 `hasMore` 和原始行号；结果单元格总量另有 512KiB 限制。查询超时 5 秒，避免把大文件无界展开给模型。

例如查历史报价时，Agent 先获知 `Catalog` 的 A 列是 SKU、B 列是月份、E 列是价格，再查询：

```json
{
  "documentId": "从授权文档列表取得的实际ID",
  "sheet": "Catalog",
  "filters": [
    {"column": "A", "op": "eq", "value": "HW-002499"},
    {"column": "B", "op": "eq", "value": "2026-11"}
  ],
  "limit": 20
}
```

样例返回价格 `888.25`，引用 `Catalog!A50000:I50000`；上一月价格来自 `Catalog!A47500:I47500`。历史 Excel 报价和数据库当前售价分别取证，不能互相替代。

## 数据和权限语义

XLSX 的数字、日期和布尔值保留类型。CSV 默认按文本处理，保留 `0012` 这样的前导零编号；如需数值范围查询，应使用明确数字类型的 XLSX 或业务数据库。首个非空行为表头，A/B/C 等列标稳定存在，重复或空白表头不会产生重复列键。

公式只读文件保存时的计算缓存，既不执行公式，也不执行宏或外部链接。没有缓存时返回单元格警告，不把缺失结果解释为零。缓存可能已经过期，数据准确性仍取决于上传者先在 Excel 中重新计算和保存。下载接口经用户鉴权，返回与上传相同的原始字节。

一份工作簿及其所有工作表共享一个文件 ACL，支持本人、部门和本租户。普通系统管理角色不会自动取得别人的私有文件读取权；显式 `novex_super_admin` 是全知识库读取例外，当前只有 `admin` 获得此角色。它不修改文件原有的拥有者、企业或共享范围。**Excel 文件 ACL 不等同于数据库的行权限或字段权限。** 含全员工资的工作簿不能仅靠普通系统角色隐藏某些工作表或行；需要这类隔离时，应把数据作为业务资源接入，按用户与外部员工/部门 ID 的关联强制过滤。

## 当前容量与边界

- XLSX / CSV：原件最多 32MiB，最多 20 万数据行、200 万单元格/公式计数、128 列、32 个工作表；XLSX 解压总体积另有 256MiB 限制。
- 文字类上传最多 16MiB，转换后的 Markdown 最多 2MiB。扫描 PDF/OCR、`.xls`、`.xlsm`、文档版本历史未实现。
- 当前授权目录在运行开始时物化。大量 Markdown 文件会增加启动复制与目录索引成本；本次以 80 份企业文档验证，不代表已验证百万文件规模。
- 字面关键词检索不提供语义召回保证。Agent 可以拆分关键词、选择相关资料；不承诺任意同义词或无关键词提问必然命中。
- 业务与表格查询返回有限页。尚未提供全量 `SUM` / `COUNT` 聚合工具，模型不得把一页的合计宣称为全公司或全文件总额。

真实五万行 Excel、公式缓存、历史报价、权限与分页检查见 `scripts/check_spreadsheets.py`；含两种实际 Agent 的企业问答回归见 `scripts/check_enterprise.py`。本次运行数据记录在 [验证记录](verification.md) 与本地 `.local/` 报告，性能数字应按各自测试范围解读。
